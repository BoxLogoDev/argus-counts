# Argus (신규 제작)

창고 재고실사 코파일럿. 단말로 빈(bin)을 촬영하면 SAM 3.1이 수량을 세고 장부와 대조해 차이 리포트를 만든다. Meta Global AI Developer Hackathon(2026) 출품작으로, 이 저장소의 모든 코드는 행사 기간 안에 새로 작성했다.

## 구성 (계획)

- `terminal/` — 단말 플로우: 촬영 → SAM 3.1 계수 → 장부 대조 → 차이 리포트. Pi 5 + 카메라 실기 기준, 도착 전에는 시뮬레이터로 개발한다.
- `console/` — 관리자 웹 콘솔: 실사 세션 목록, 차이 목록, 요약 지표(실사 완료 수·일치율·불일치 내역).
- `qa/` — 기준값 대조 하네스: 데모 빈 6개의 장부·실측 시나리오를 단언으로 검증한다.
- `docs/` — 제출 스토리와 데모 영상 대본.

## SAM 3.1 연동

- 연동 지점은 Meta Model API다.
- 개발은 모의 어댑터로 진행한다. 환경변수 `SAM_API_BASE_URL`과 `SAM_API_KEY`를 설정하면 실호출 어댑터가 선택된다. SAM 3.1 실호출은 2026-10-30 단일 빈 스모크로 검증했다(커넥터 경유, 생성한 가상 창고 사진에서 박스 14개 계수). 전체 세션 실호출은 2026-10-30 커넥터 브리지로 통과했다(같은 가상 사진 재사용, 빈별 정확도 아님). 빈별 실호출은 2026-10-31 커넥터 브리지로 통과했다(가상 사진의 서로 다른 잘라내기 6장, 실제 빈 촬영 아님). 파일 입력 경로 실호출은 2026-11-02 커넥터 브리지로 통과했다(가상 사진의 서로 다른 잘라내기 6장, 파일 기반 입력이며 Pi 실촬영 아님). 이 환경의 기본 실행은 모의 어댑터 기준이다. 규격 의존 부분은 어댑터의 요청 구성·응답 해석 두 지점에 격리돼 있고, 가짜 전송(fake transport) 테스트로도 검증했다.
- 모의 결과는 화면에서 '모의'로 구분해 표기한다.

## 실행법 (초안)

아직 골격 단계라 실행 명령은 구성 요소가 들어오는 대로 이 문서에 확정해 적는다.

- 콘솔: 프로젝트 루트에서 `python3 -m console.server` (기본 http://127.0.0.1:8765, `/`는 화면 — 요약 지표·준비 상태(SAM 실호출 준비와 Pi 실촬영 준비의 블로커를 분리 표기하며, 준비 완료는 실호출·실촬영 성공을 뜻하지 않는다)·차이 목록·조치 우선순위·영향 수치 포함, `/api/report`는 JSON, `/api/readiness`는 준비 상태 JSON(실제 API 호출·촬영 없음, 환경변수 값 미포함), `/sessions`는 데모 세션 3개 목록 화면, `/sessions/<id>`는 세션 상세, `/api/sessions`·`/api/sessions/<id>`는 JSON)
- 단말 시뮬레이터: 프로젝트 루트에서 `python3 -m terminal.simulator` (JSON 리포트 출력, `--out <경로>`로 저장 가능)
- 차이 리포트: 프로젝트 루트에서 `python3 -m terminal.report` (텍스트 리포트, `--json`으로 조치 우선순위 payload, `--out <경로>`로 저장 가능)
- 사진 입력 파이프라인: 프로젝트 루트에서 `python3 -m terminal.photo_intake --capture A-01-02=<사진경로> [--capture <빈>=<사진경로> ...]` (파일 기반 입력이며 Pi 실촬영이 아니다. 사진 파일의 크기·SHA-256을 기록하고 기존 계수→대조 흐름에 태우며, 계수는 어댑터 경유·모의 기준이다. 파일 입력 경로 실호출은 2026-11-02 커넥터 브리지로 통과했다(가상 사진의 서로 다른 잘라내기 6장, 파일 기반 입력이며 Pi 실촬영 아님). Pi 도착 후에는 카메라가 만든 사진 파일을 같은 형식으로 넘긴다)
- Pi 카메라 캡처: 프로젝트 루트에서 `python3 -m terminal.pi_capture --probe` (libcamera-still·raspistill 명령 존재만 탐지하며 명령을 실행하지 않는다. `--capture <빈>=<출력경로>`로 캡처를 시도할 수 있으나 Pi 실촬영 검증 전이며, 이 VM처럼 카메라 명령이 없는 환경에서는 available=false로 보고하고 캡처는 PiCaptureError로 실패한다. 가짜 파일로 대체하지 않는다)
- Pi 촬영 세션: 프로젝트 루트에서 `python3 -m terminal.pi_session --out-dir <캡처 디렉터리> [--bin <빈> ...] [--session-id <id>] [--out <경로>]` (Pi 캡처 경계와 사진 입력 파이프라인을 이어 한 번의 호출로 촬영→계수→대조→리포트를 수행한다. 카메라 명령이 없으면 PiCaptureError로 실패하고 종료코드 1이며 가짜 파일로 대체하지 않는다. Pi 실촬영 검증 전이며 계수는 모의 어댑터 기준이고 리포트의 capture_source는 pi-camera, probe와 honesty에 검증 전임이 기록된다)
- 단위 테스트: 프로젝트 루트에서 `python3 -m unittest discover -s tests` (현재 854개)
- QA 하네스: 프로젝트 루트에서 `python3 -m qa` (기준값 대조 체크 17개, 전부 통과 시 종료코드 0·실패 시 1)
- standalone 점검: 프로젝트 루트에서 `python3 -m qa.standalone` (필수 파일·회사 식별자/비밀 패턴·정직성 표기·현재형 주장 감사 체크 6개 — 주장 감사는 qa.claims_audit를 재사용해 통합했다)
- 현재형 주장 감사: 프로젝트 루트에서 `python3 -m qa.claims_audit` (README·제출 문서에서 SAM 실호출·Pi 실촬영 같은 미실시 사항을 이미 한 것처럼 단정하는 문장을 감사. 정직성 표기가 없는 단정만 위반으로 잡으며, 전부 통과 시 종료코드 0)
- 날짜·시각 기준 일관성 감사: 프로젝트 루트에서 `python3 -m qa.date_consistency [--json]` (날짜 판정 모듈에 시간대 없는 날짜·시각 호출이 없는지, 명시적 UTC 현재 시각이 허용 목록 5개 파일·7곳 안에서만 쓰이는지, 폴백 결정·영상 선택·제출 마감의 기본 날짜·시각이 실제 KST 계산과 일치하는지를 감사한다. 세션 식별자와 생성 시각의 명시적 UTC는 날짜 판정이 아니며, 감사 통과는 제출 준비 완료를 뜻하지 않는다)
- SAM 실호출 전환 준비 점검: 프로젝트 루트에서 `python3 -m qa.sam_readiness [--credit-confirmed] [--json]` (실제 API를 호출하지 않고 크레딧 입금 확인 여부와 SAM_API_BASE_URL·SAM_API_KEY 존재 여부만 점검한다. 환경변수 값은 출력하지 않는다. 준비 완료는 실호출 성공을 뜻하지 않으며, 현재 기본 환경에서는 블로커 3건으로 READY_FOR_LIVE_CALL: false다)
- SAM 단일 빈 스모크: 프로젝트 루트에서 `python3 -m qa.sam_smoke [--credit-confirmed] [--json] [--bin <빈>]` (준비 점검을 통과하지 못하면 실제 API를 호출하지 않고 차단 보고만 낸다. 통과한 경우에만 빈 1개를 시도하며, 성공해도 전체 세션 성공을 뜻하지 않고 실패하면 모의로 대체하지 않는다. 현재 기본 환경에서는 블로커 3건으로 차단되고 종료코드 1이다)
- SAM 전체 세션 실호출: 프로젝트 루트에서 `python3 -m qa.sam_session [--credit-confirmed] [--json] [--image <빈>=<경로> ...] [--image-ref <경로>]` (준비 점검을 통과하지 못하면 어떤 빈도 호출하지 않고 차단 보고만 낸다. 통과한 경우에만 데모 빈 6개 전부를 계수해 장부와 대조한 세션 리포트를 내며, 한 빈이라도 실패하면 세션 전체를 실패로 보고하고 모의로 대체하지 않는다. 전체 세션 실호출이어도 Pi 실촬영이 아니며 사진은 호출자가 제공한 것이다. 현재 기본 환경에서는 블로커 3건으로 차단되고 종료코드 1이다)
- SAM 빈별 서로 다른 사진 실호출: 프로젝트 루트에서 `python3 -m qa.sam_per_bin [--credit-confirmed] [--json] [--image <빈>=<경로> ...]` (준비 점검을 통과하지 못하면 어떤 빈도 호출하지 않고, 빈 6개마다 서로 다른 사진 파일이 갖춰지지 않았거나 두 빈이 같은 사진이면 SHA-256 검사에서 호출 없이 실패로 보고한다. 통과한 경우에만 빈마다 그 빈의 사진으로 계수해 빈별 사진 해시와 함께 대조 리포트를 내며, 실패하면 모의로 대체하지 않는다. 빈별 사진은 호출자가 제공한 가상 사진의 서로 다른 잘라내기이며 실제 빈 촬영이나 Pi 실촬영이 아니다. 현재 기본 환경에서는 블로커 3건으로 차단되고 종료코드 1이다)
- SAM 실호출 증거 검증: 프로젝트 루트에서 `python3 -m qa.sam_live_evidence --file <증거 JSON 경로> [--json]` (커넥터 브리지로 수행한 SAM 3.1 빈별 실호출의 증거 JSON을 다시 읽어 bridge·endpoint·source=sam·빈 순서·diff·판정·빈별 사진 해시 서로 다름·summary 재계산을 대조하는 검증 하네스. 실제 API를 호출하지 않고 환경변수 값을 다루지 않으며, 증거 검증 통과는 실제 빈 촬영이나 Pi 실촬영, 제출 준비 완료를 뜻하지 않는다)
- SAM 전체 세션 실호출 증거 검증: 프로젝트 루트에서 `python3 -m qa.sam_session_evidence --file <증거 JSON 경로> [--json]` (커넥터 브리지로 수행한 SAM 3.1 전체 세션 실호출의 증거 JSON을 다시 읽어 bridge·endpoint·source=sam·빈 순서·장부 수량·diff·판정·빈별 사진 해시 서로 다름·summary 재계산을 대조하는 검증 하네스. 실제 API를 호출하지 않고 환경변수 값을 다루지 않으며, 증거 검증 통과는 실제 빈 촬영이나 Pi 실촬영, 제출 준비 완료를 뜻하지 않는다)
- SAM 파일 입력 경로 실호출 증거 검증: 프로젝트 루트에서 `python3 -m qa.sam_photo_evidence --file <증거 JSON 경로> [--json]` (커넥터 브리지로 수행한 SAM 3.1 파일 입력 경로(terminal.photo_intake) 실호출의 증거 JSON을 다시 읽어 bridge·endpoint·path(photo_intake)·source=sam·capture_source=file·빈 순서·item_code·장부 수량·diff·판정·빈별 사진 해시 서로 다름·사진 크기·확장자·image_ref·summary 재계산을 대조하는 검증 하네스. 실제 API를 호출하지 않고 환경변수 값을 다루지 않으며, 증거 검증 통과는 실제 빈 촬영이나 Pi 실촬영, 제출 준비 완료를 뜻하지 않는다)
- 데모 영상 제출 후보 선택: 프로젝트 루트에서 `python3 -m qa.video_selection [--date YYYY-MM-DD] [--device-confirmed] [--json]` (qa.fallback_decision 판정을 재사용해 패키징 시점의 제출 후보 MP4를 정하고, 고른 파일의 존재·크기를 대조하는 점검 하네스. 결정일 전이면 기본 영상이 기본 후보, 결정일에 폴백이 채택되면 폴백 렌더가 후보, Pi가 준비되면 기본 영상이 후보다. 실제로 제출하지 않고 영상을 새로 만들지도 않으며, 선택은 제출 준비 완료를 뜻하지 않고 폴백 영상은 Pi 실촬영이 아니다. 현재 2026-11-01 기준 판정은 pending이라 기본 영상이 기본 후보이며 SUBMISSION_READY: false다)
- Pi 실촬영 준비 점검: 프로젝트 루트에서 `python3 -m qa.pi_readiness [--device-confirmed] [--json]` (실제 촬영을 하지 않고 Pi 장치 도착의 외부 확인 여부와 카메라 명령(libcamera-still·raspistill) 존재만 점검한다. 카메라 명령을 실행하지 않고 존재만 탐지하며, 준비 완료는 Pi 실촬영 성공을 뜻하지 않는다. Pi 실촬영 검증 전이며, 현재 이 환경에서는 블로커 2건으로 READY_FOR_REAL_CAPTURE: false다)
- Pi 단일 빈 스모크: 프로젝트 루트에서 `python3 -m qa.pi_smoke [--device-confirmed] [--json] [--bin <빈>] [--out-dir <캡처 디렉터리>]` (준비 점검을 통과하지 못하면 실제로 촬영하지 않고 차단 보고만 낸다. 통과한 경우에만 빈 1개의 촬영 세션을 시도하며, 성공해도 전체 세션 성공이나 Pi 실촬영 검증 완료를 뜻하지 않고 실패하면 가짜 파일로 대체하지 않는다. 현재 이 환경에서는 블로커 2건으로 차단되고 종료코드 1이다)

제출 준비 완료가 아니다. package-export는 제출 패키지 내보내기를 CLI 임시 staging 구동과 프로세스 내 build/validate로 구동해 제출물 18개 복사·SHA-256 재대조·매니페스트·복사본 변조 탐지를 확인하고, 깨끗한 staging의 `--verify-dir` 재검증 증거(텍스트·JSON·읽기 전용·변조 탐지·매니페스트 없음·인자 충돌)를 package-export-verify.json/txt로 남기고, 같은 제출물의 최종 묶음(qa.final_package) 보고와 내보내기 필드를 교차 대조하는 증거(fp_cross_ok)도 남기며 실제로 제출하지 않고, 내보내기가 온전해도 제출 가능을 뜻하지 않으며 Pi 실촬영 검증 전이다. final-package는 제출 패키지 최종 묶음을 CLI 기준 시각·날짜 고정 구동(인벤토리 18/18·마감 전·폴백 pending·블로커 잔존 blocked·마감 경과 overdue·잘못된 날짜 차단)과 프로세스 내 evaluate/build/validate·변조 탐지로 구동하며, 데모 영상 선택 증거(selected_video·selection_reason·selected_size를 pending 기본 영상과 due 가정 폴백 렌더로 파일 실측 크기·build 실측과 교차 대조하고 변조를 탐지)와 패키지 내보내기 재검증 증거(export_verify_verified·export_verify_copied_files·export_verify_total_bytes를 CLI·JSON·build 실측과 교차 대조하고 변조를 탐지)와 마감 잔여시간 독립 교차 증거(같은 기준 시각의 qa.deadline 보고 remaining_seconds·status를 최종 묶음과 교차 대조하고 deadline_remaining_seconds·deadline_status_from_deadline를 남김)를 summary에 남기고 실제로 제출하지 않으며, 패키지 준비 상태는 제출 완료를 뜻하지 않고 Pi 실촬영 검증 전이다. demo-video-draft는 조립 매니페스트 컷 3의 폴백 참조를 build_fallback_ref·validate_assembly 변조/누락 탐지로 구동해 assembly-fallback.json 증거를 남기고, 폴백 렌더 변형 MP4를 ffprobe 탐침과 컷 3 폴백 패널 4줄·build_fallback_manifest 변조 탐지로 구동해 fallback-render.json 증거를 남기며, 폴백은 Pi 실촬영이 아니고 컷 3 전환 확정도 아니다 package-archive는 제출 패키지 영속 아카이브를 CLI 임시 디렉터리 구동과 프로세스 내 build_archive·validate_archive로 구동해 제출물 18개 복사·선택 영상(폴백 렌더) SHA-256·매니페스트·변조 탐지를 확인하고, 깨끗한 아카이브의 `--verify-dir` 재검증 증거(텍스트·JSON·읽기 전용·변조 탐지·매니페스트 없음·인자 충돌)를 package-archive-verify.json/txt로 남기며 실제로 제출하지 않고, 아카이브가 archived여도 제출 가능을 뜻하지 않으며 Pi 실촬영 검증 전이다. date-consistency는 날짜·시각 기준 일관성 감사 하네스를 CLI와 프로세스 내 build/validate로 구동해 KST 기본값 일치·시간대 없는 호출 없음·허용 목록 밖 UTC 없음·변조 탐지를 확인하며 실제로 제출·촬영·호출하지 않고, 감사 통과는 제출 준비 완료를 뜻하지 않는다.
