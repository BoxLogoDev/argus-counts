# Argus. 창고 재고실사 코파일럿

Argus는 단말로 빈(bin)을 촬영하면 SAM 3.1이 수량을 세고 장부와 대조해 차이 리포트를 만드는 창고 재고실사 코파일럿이다.

테마는 Build for Your World를 전제로 한다. 주인님 최종 확정 전 가안이다.

## 문제

창고 재고 실사는 빈마다 물건을 세고 장부와 맞추는 작업이다.
빈이 늘면 세는 시간도 늘어난다.
사람이 세면 누락과 중복이 생긴다.
기록이 늦어지면 장부와 실물이 어긋난다.

EWM 실무 일반론으로 보면 재고 차이는 입고와 출고 기록의 지연에서 생긴다.
이동과 반품 기록이 비어도 차이가 생긴다.
오적재가 있어도 차이가 생긴다.
차이를 찾은 뒤에도 어느 빈부터 확인할지가 남는다.
실사의 병목은 세는 일에만 있지 않다.
차이를 정리하고 조치 순서를 정하는 일도 병목이다.

## 해결

워크플로는 네 단계다.

1. 촬영. 단말로 빈을 촬영한다.
2. SAM 계수. SAM 3.1 어댑터 경계에서 수량을 센다.
3. 장부 대조. 장부 수량과 실측 수량을 빈마다 비교한다.
4. 차이 리포트. 일치와 불일치를 나누고 조치 우선순위를 붙인다.

대조 결과는 세 가지로 판정한다.
장부와 실측이 같으면 일치(match)다.
실측이 적으면 부족(short)이다.
실측이 많으면 초과(over)다.

리포트는 불일치 빈만 골라 조치 우선순위를 만든다.
정렬 기준은 절대 차이 큰 순이다.
동률이면 bin_id 오름차순이다.
부족이면 재촬영으로 재확인하고 입고와 출고 기록을 대조하게 안내한다.
초과이면 오적재 여부를 확인하고 이동과 반품 기록을 대조하게 안내한다.

관리자 웹 콘솔은 실사 세션 목록을 보여준다.
콘솔은 차이 목록도 보여준다.
요약 지표로는 실사 완료 수와 일치율과 불일치 내역을 보여준다.

## 이번에 만든 것과 기존에 있던 것

기존에 있던 것은 Meta SAM 3.1과 Meta Model API와 Python 표준 라이브러리와 하드웨어 플랫폼이다. 이번에 만든 것은 이 저장소의 모든 코드와 문서이며 2026-10-27 이후 해커톤 기간에 새로 작성했다.

모든 코드는 해커톤 기간인 2026-10-27 이후에 새로 작성됐다.

## Meta AI 도구 활용

연동 지점은 Meta Model API다.
SAM 3.1 호출은 어댑터 경계 뒤에 둔다.
대조 엔진과 리포트와 콘솔은 그 경계의 결과만 받는다.
그래서 계수 출처가 바뀌어도 대조 로직은 그대로다.

전환 구조는 환경변수 기반이다.
`SAM_API_BASE_URL`과 `SAM_API_KEY`를 설정하면 실호출로 전환된다.
설정하지 않으면 모의 어댑터로 동작한다.
모의 결과는 화면에서 모의로 구분해 표기한다.
리포트에서도 계수 출처를 모의로 표기한다.

현재 상태는 분명하다.
SAM 3.1 실호출은 2026-10-30 단일 빈 스모크로 검증했다.
스모크에서는 생성한 가상 창고 사진에서 박스 14개를 셌다(장부 8, 차이 +6).
현재 데모는 모의(mock) 어댑터로 동작한다.
전체 세션 실호출은 2026-10-30 커넥터 브리지로 통과했다(같은 가상 사진 재사용, 빈별 정확도 아님).
모의 결과를 실호출 결과로 주장하지 않는다.

Pi 실기 카메라 연동은 아직 검증 전이다.
단말 플로우는 Pi 5와 카메라 실기를 기준으로 설계했다.
실기가 도착하기 전에는 시뮬레이터로 개발한다.
실기 검증이 끝났다고 주장하지 않는다.

## 기술 깊이

대조 엔진은 빈마다 장부 수량과 실측 수량과 차이와 판정을 만든다.
요약 지표는 실사 완료 빈 수와 일치 수와 불일치 수를 포함한다.
요약 지표는 일치율과 절대 차이 합계와 순차이도 포함한다.
리포트 모듈은 사람이 읽는 한국어 텍스트 리포트를 만든다.
같은 모듈은 콘솔과 외부 연동용 구조화 payload도 만든다.
표준 라이브러리만 쓴다.

QA 하네스는 기준값 대조 체크 17개를 실행한다.
기준값은 하네스 파일에 리터럴로 고정한다.
소스 데이터에서 기준값을 복사하지 않는다.
그래서 소스 데이터나 대조 엔진이 드리프트하면 하네스가 실패로 잡아낸다.
체크 범위는 빈별 장부와 실측과 판정과 차이다.
부족 빈과 초과 빈의 정확한 집합도 체크한다.
요약 지표와 모의 출처 표기도 체크한다.
콘솔 뷰 모델의 지표와 차이 목록이 리포트와 같은지도 체크한다.
전부 통과하면 종료코드는 0이다.
하나라도 실패하면 종료코드는 1이다.

단위 테스트는 588개다.

예시는 전부 가상 데모 데이터다.
데모 빈은 6개다.
일치는 4건이다.
불일치는 2건이다.
부족은 A-01-02이며 장부 8에서 실측 5로 차이 -3이다.
초과는 B-01-02이며 장부 6에서 실측 9로 차이 +3이다.
절대 차이 합계는 6이다.
순차이는 0이다.
일치율은 66.7%다.

## 영향

데모 기준. 빈 6개 중 불일치 2건과 절대 차이 6개와 일치율 66.7%를 한 번의 대조로 정리하고 조치 우선순위까지 붙인다.

## 현재 상태

현재 제출 블로커는 한 건이다.

- `pi_real_capture_pending` — Pi 실촬영 검증 전이라 데모 컷 3은 플레이스홀더이며 Pi 도착 후 교체 예정이다.

`SUBMISSION_READY: false` — 기계 점검이 통과해도 위 블로커가 남아 있는 동안 제출 가능 상태가 아니다.
Pi 실기 카메라 연동은 아직 검증 전이다.
SAM 3.1 실호출은 2026-10-30 단일 빈 스모크로 검증했다.
