# Argus 검증 기능 지도

이 디렉터리는 Argus의 사용자 대면 동작을 검증하는 유지 정본이다. 구동 전에 이 색인을 읽고, 검증할 기능 파일을 절차로 삼는다.

## 기준 전제

- 검증은 자기가 띄운 서버만 구동한다. 헬퍼는 127.0.0.1 임시 포트(포트 0, OS 배정)를 쓰고, 8765의 상주 인스턴스는 구동하지 않는다.
- 모든 응답은 모의 어댑터 기준이다: JSON `source`는 `mock`, 화면에는 `모의 데이터` 표기가 있어야 한다. 환경변수 `SAM_API_BASE_URL`·`SAM_API_KEY`는 비운다.
- 로컬 HTTP는 프록시를 우회한다: urllib에 `ProxyHandler({})`를 명시한 전용 오프너를 쓴다.
- 데모 기준값: 빈 6개, 일치 4, 불일치 2, 절대 차이 6, 순 차이 0, 일치율 66.7%. 세션은 3개(`DEMO-20261027-A`, `DEMO-20261027-B` 전부 일치, `DEMO-20261026-A`)다.
- 증거는 `/tmp/argus-verify-evidence/<run-id>/`에 남기고, 서버를 종료한 뒤에도 증거가 남았는지 확인한다.

## 구동 규약

- 각 절차는 기준 상태에서 시작한다. 앱에 상태가 없으므로 재시작이 곧 초기화다.
- 명령은 글자 그대로 실행한다. 경로나 마커를 바꾸지 않는다.
- 도달할 수 없는 경로는 시도한 명령과 충족되지 않은 전제를 보고한다. 다른 경로로 통과한 것으로 치지 않는다.

## 증명과 보고

- 행동과 결과 상태를 함께 남긴다: 요청·상태 코드·응답 원문·종료 코드.
- 화면 증거에는 앱 이름과 모의 표기가 같이 보여야 한다.
- CLI 증거에는 명령, stdout, stderr, 종료 코드를 남긴다.
- 생성 파일을 만드는 기능은 파일 실물과 내용을 두 번째 확인으로 읽는다.

## 기능 파일 규약

각 파일은 H1 제목과 한 문단 설명 뒤에 정확히 네 개의 H2를 이 순서로 가진다.

1. `Sub-features`는 짧은 ID로 동작을 나눈다.
2. `How to get to it (user POV)`는 사용자 진입점을 모두 적는다.
3. `Driving it with verify_argus.py`는 `Preconditions:`로 시작하고, 행동·명령·관찰 결과가 짝을 이룬다.
4. `Gotchas`는 검증이 무효가 되는 함정을 적는다.

## 기능 목록

- [콘솔 홈](console-home.md) — 요약 지표·차이 목록·조치 우선순위·영향 한 줄이 있는 홈 화면과 `/api/report` JSON.
- [단말 시뮬레이터](terminal-simulator.md) — 촬영→계수→대조 흐름을 CLI로 구동해 JSON 리포트를 얻는다.
- [세션 목록](session-list.md) — 데모 세션 3개의 목록·상세 화면과 JSON, 없는 세션의 404.
- [차이 리포트](difference-report.md) — 조치 우선순위와 `데모 기준` 영향 한 줄이 있는 텍스트·JSON 리포트.
- [데모 영상 초안](demo-video-draft.md) — 180초 MP4 초안 렌더와 컷 3 플레이스홀더 표기 확인.
- [사진 입력](photo-intake.md) — 파일 기반 사진 입력 파이프라인(Pi 실촬영 아님)을 가짜 사진 6장으로 구동해 계수→대조 리포트와 사진 SHA-256 기록을 얻는다.
- [제출 전 전수 점검](pre-submission.md) — 제출 전 기계적 점검 6종과 블로커 2건 분리 보고를 구동한다. 기계적 통과에도 제출 가능은 아니다.
- [Pi 캡처](pi-capture.md) — Pi 카메라 캡처 경계(명령 탐지·부재 시 기대 실패·가짜 runner 성공)를 구동한다. Pi 실촬영 검증 전이다.
- [Pi 촬영 세션](pi-session.md) — Pi 캡처→사진 입력→대조 통합 세션을 CLI 기대 실패와 가짜 which/runner 주입으로 구동한다. Pi 실촬영 검증 전이다.
- [SAM 실호출 준비](sam-live.md) — SAM 실호출 경계(가짜 transport 성공·해석 변형·실패 차단)를 구동한다. SAM 실호출 검증 전이며 실제 API 호출은 없다.
- [SAM 실호출 전환 준비 점검](sam-readiness.md) — SAM 실호출 전환 준비 점검(크레딧·환경변수 존재 여부만, 실제 API 호출 없음)을 구동한다. 준비 완료는 실호출 성공이 아니다.
- [제출 런북](submission-runbook.md) — 제출 런북의 절 순서·블로커 2건·최종 점검 명령 8종과 SUBMISSION_READY: false를 구동한다. 제출 준비 완료가 아니다.
- [Pi 실촬영 준비 점검](pi-readiness.md) — Pi 실촬영 준비 점검(장치 도착 외부 확인·카메라 명령 존재만 탐지, 실제 촬영 없음)을 구동한다. 준비 완료는 Pi 실촬영 성공이 아니다.
