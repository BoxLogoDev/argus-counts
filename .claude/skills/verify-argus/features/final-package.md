# 제출 패키지 최종 묶음

제출 패키지 최종 묶음은 `qa.final_package`가 제출물 인벤토리·제출 마감·Pi 폴백 결정 세 보고와 패키지 내보내기 실측(임시 staging 복사 대조), 데모 영상 선택 보고를 모아 패키지 상태를 판정하는지 검증하는 절차다. 이 검증은 실제로 제출하지 않는다: CLI에 기준 시각과 날짜를 명시해 구동하고 프로세스 내 `evaluate_final_package`·`build_final_package`·`validate_final_package`으로만 확인한다. 패키지 준비 상태는 제출 완료를 뜻하지 않으며, Pi 실촬영 검증 전이고 수치는 데모 기준이다. 패키지 날짜 목표는 2026-11-03이다.

## Sub-features

- `final-package-cli-blocked` CLI 블로커 잔존 판정: `python3 -m qa.final_package --now 2026-10-31T04:50:00+09:00 --date 2026-10-31`이 종료코드 0을 내고, 텍스트에 `STATUS: blocked`·`PACKAGE_DATE_TARGET: 2026-11-03`·`INVENTORY_PRESENT: 18`·`INVENTORY_TOTAL: 18`·`DEADLINE_STATUS: before_deadline`·`REMAINING_SECONDS: 454200`·`FALLBACK_STATUS: pending`·`SUBMISSION_READY: false`가 있으며, `--json`에서는 status blocked·inventory_missing []·fallback_adopted false·blockers [`pi_real_capture_pending`]·submission_ready false·honesty 3종(실제로 제출하지 않는다, 제출 완료를 뜻하지 않는다, Pi 실촬영 검증 전)임을 확인한다.
- `final-package-cli-overdue` CLI 마감 경과 판정: `python3 -m qa.final_package --now 2026-11-05T11:00:00+09:00 --date 2026-10-31 --json`이 종료코드 1을 내고 status overdue·deadline_status overdue임을 확인한다.
- `final-package-evaluate` 프로세스 내 판정식: `evaluate_final_package`가 블로커 잔존 시 blocked, 블로커가 없으면 ready_for_packaging, 제출물이 누락되면 incomplete, 마감 경과 시 overdue를 내고, `build_final_package`가 기준 시각·날짜에서 blocked를 내며, 모든 보고가 `validate_final_package`에서 문제 0건임을 확인한다. 구동 함수는 `drive_final_package`다.
- `final-package-tamper` 변조 탐지: status를 바꾸면 status 문제를, inventory_present를 바꾸면 inventory_present 문제를, submission_ready를 true로 바꾸면 submission_ready 문제를, export_copied를 바꾸면 export_copied 문제를 `validate_final_package`가 각각 지목함을 확인한다.
- `final-package-export-evidence` 패키지 내보내기 증거: CLI 텍스트의 `EXPORT_COPIED: 18`·`EXPORT_TOTAL: 18`·`EXPORT_MISSING: []`와 JSON의 export_copied·export_total·export_missing·export_total_bytes(양의 정수)를 확인하고, export 필드가 인벤토리 필드(export_copied=inventory_present·export_total=inventory_total·export_missing=inventory_missing)와 어긋나지 않는지 교차 대조한다. `build_final_package` 실측의 export_total_bytes가 CLI blocked 보고와 같은지도 대조하며, 증거 summary에 `export_copied`·`export_total`·`export_missing`·`export_total_bytes`·`built_export_total_bytes`·`export_incomplete_status`·`export_tamper_detected`를 남긴다. 내보내기 실측은 임시 staging 복사·대조까지만이며 실제로 제출하지 않는다.
- `final-package-export-verify-evidence` 패키지 내보내기 재검증 증거: CLI 텍스트의 `EXPORT_VERIFY_VERIFIED: true`·`EXPORT_VERIFY_COPIED_FILES: 18`·`EXPORT_VERIFY_TOTAL_BYTES`(JSON의 export_total_bytes와 일치)와 JSON의 export_verify_verified(true)·export_verify_copied_files(18이며 export_copied와 일치)·export_verify_total_bytes(양의 정수이며 export_total_bytes와 일치)를 확인하고, 결정일 가정 날짜 CLI에서도 재검증 필드가 같은 값을 내는지, `build_final_package` 실측의 export_verify_*가 CLI blocked 보고와 같은지 교차 대조한다. export_verify_verified를 false로 바꾸면 export_verify_verified 문제를, export_verify_copied_files를 바꾸면 export_verify_copied_files 문제를, export_verify_total_bytes를 바꾸면 export_verify_total_bytes 문제를, export_verify_verified를 None으로 바꾸면 나머지 재검증 필드 문제를 각각 지목하는 변조 탐지도 확인하며, 증거 summary에 `export_verify_verified`·`export_verify_copied_files`·`export_verify_total_bytes`·`built_export_verify_verified`·`built_export_verify_copied_files`·`built_export_verify_total_bytes`·`export_verify_tamper_detected`를 남긴다. 재검증은 같은 staging을 매니페스트만 읽어 다시 대조하는 것까지만이며 실제로 제출하지 않고, 재검증 통과는 제출 준비 완료를 뜻하지 않으며 Pi 실촬영 검증 완료도 아니다.
- `final-package-deadline-cross-evidence` 마감 잔여시간 독립 교차 증거: 헬퍼가 최종 묶음과 같은 기준 시각(`--now 2026-10-31T04:50:00+09:00`)으로 `qa.deadline` CLI를 `--json`으로 따로 실행해 status before_deadline·remaining_seconds 454200(양의 정수)·deadline_kst `2026-11-05T11:00:00+09:00`·blockers [`pi_real_capture_pending`]·submission_ready false를 확인하고, 최종 묶음 blocked 보고의 remaining_seconds·deadline_status가 그 독립 마감 보고의 remaining_seconds·status와 각각 같은지 교차 대조한다. 증거 summary에 `deadline_remaining_seconds`·`deadline_status_from_deadline`를 남기고 deadline CLI 원문은 `final-package-deadline.json` 증거로 남는다. 마감 교차 대조는 남은 시간 계산 대조까지만이며 실제로 제출하지 않고, 마감 전이어도 제출 준비 완료를 뜻하지 않는다.
- `final-package-video-selection-evidence` 데모 영상 선택 증거: CLI 텍스트의 `SELECTED_VIDEO: demo/assets/argus-demo-draft.mp4`·`SELECTION_REASON: pending_default`·`SELECTED_SIZE`(기본 영상 파일 실측 크기와 일치)와 JSON의 selected_video·selection_reason·selected_size를 확인하고, 결정일 가정 날짜(`--date 2026-11-02`) CLI에서는 fallback_status fallback_due·selected_video `demo/assets/argus-demo-fallback-draft.mp4`·selection_reason fallback_due·selected_size가 폴백 영상 파일 실측 크기와 일치함을 확인한다. `evaluate_final_package`의 pending 쌍과 fallback_due 쌍이 모두 `validate_final_package`에서 문제 0건이고, `build_final_package` 실측(pending 날짜·due 날짜)이 CLI 보고와 같은 selected_video·selected_size를 내는지 교차 대조한다. selected_video를 다른 후보로 바꾸면 selected_video 문제를, selection_reason을 바꾸면 selection_reason 문제를, selected_size를 0으로 바꾸면 selected_size 문제를, selected_video를 None으로 바꾸면 selection_reason/selected_size 문제를 각각 지목하는 변조 탐지도 확인하며, 증거 summary에 `selected_video`·`selection_reason`·`selected_size`·`due_selected_video`·`due_selection_reason`·`due_selected_size`·`due_fallback_status`·`built_selected_video`·`built_selected_size`·`built_due_selected_video`·`built_due_selected_size`·`video_tamper_detected`·`selected_video_tamper_detected`·`selection_reason_tamper_detected`·`selected_size_tamper_detected`를 남긴다. 영상 선택은 실제로 제출하지 않으며 제출 준비 완료를 뜻하지 않고, 폴백 영상은 Pi 실촬영이 아니다.
- `final-package-date-evidence` 날짜 감사 독립 교차 증거: 헬퍼가 `qa.date_consistency` CLI를 `--json`으로 따로 실행해 consistent true·scanned_files(양의 정수)·problems []를 확인하고, 최종 묶음 blocked 보고의 date_consistent·date_scanned_files·date_problem_count가 그 독립 보고의 consistent·scanned_files·problems 개수와 각각 같은지 교차 대조한다. CLI 텍스트의 `DATE_CONSISTENT: true`·`DATE_SCANNED_FILES`(JSON 값과 일치)·`DATE_PROBLEM_COUNT: 0`와 `build_final_package` 실측·결정일 가정 날짜 CLI의 날짜 3필드도 함께 대조한다. date_consistent를 false로 바꾸면 date_consistent 문제를, date_scanned_files를 0으로 바꾸면 date_scanned_files 문제를, date_problem_count를 1로 바꾸면 date_problem_count 문제를, date_consistent가 None인 채 date_scanned_files만 채우면 date_scanned_files 문제를 각각 지목하는 변조 탐지도 확인하며, 증거 summary에 `date_consistent`·`date_scanned_files`·`date_problem_count`·`built_date_consistent`·`built_date_scanned_files`·`built_date_problem_count`·`date_report_consistent`·`date_report_scanned_files`·`date_report_problem_count`·`date_tamper_detected`를 남기고 독립 날짜 보고 원문은 `final-package-date.json` 증거로 남는다. 날짜 교차 대조는 날짜·시각 기준 대조까지만이며 실제로 제출하지 않고, 날짜 감사가 consistent여도 제출 준비 완료를 뜻하지 않는다.
- `final-package-invalid-date` 잘못된 날짜 차단: `python3 -m qa.final_package --date not-a-date`가 종료코드 2로 거부됨을 확인한다.

## How to get to it (user POV)

- 사용자가 닿는 진입점은 단말 CLI다: 프로젝트 루트에서 `python3 -m qa.final_package`를 실행한다. 기준 시각을 고정하려면 `--now ISO8601`을, 판정 날짜를 고정하려면 `--date YYYY-MM-DD`를, 기계가 읽을 출력이 필요하면 `--json`을 붙인다. 종료코드는 보고가 유효하고 마감이 지나지 않았으면 0, 지났으면 1, 입력이 유효하지 않으면 2다.
- 이 CLI는 실제로 제출하지 않으며, 패키지 준비 상태는 제출 완료를 뜻하지 않는다. blocked는 제출 블로커가 남아 있다는 판정일 뿐이다.
- 개발자가 경계를 점검하는 진입점은 검증 헬퍼다: `python3 .claude/skills/verify-argus/scripts/verify_argus.py --feature final-package --evidence-dir /tmp/argus-verify-evidence/<run-id>`.
- 실제 제출 경로는 이 절차의 범위가 아니다. 이 절차의 통과를 제출 완료나 제출 준비 완료로 서술하지 않는다.

## Gotchas

- 패키지 준비 상태는 제출 완료를 뜻하지 않는다. ready_for_packaging이어도 submission_ready는 항상 false다.
- blocked는 실패가 아니다. 제출물 18개가 모두 있어도 블로커 `pi_real_capture_pending`이 남아 있으면 blocked가 정답이다.
- 남은 시간과 폴백 판정은 제공된 기준 시각·날짜로만 계산한다. 기준을 고정하지 않은 구동을 결정적 증거로 쓰지 않는다.
- 마감 경과가 최우선이다. 제출물이 누락돼 있어도 deadline_status가 overdue면 status는 overdue다.
- 파일 입력 폴백은 Pi 실촬영이 아니다. fallback_status와 fallback_adopted로 Pi 실촬영 검증 완료를 주장하지 않는다.
